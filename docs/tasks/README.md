## How to review

Change each **Decision** from `Review` to `Execute`, `Defer`, or `Dismiss`; add a short
reason for a deferral or dismissal. Use `In progress` and `Done` when carrying out accepted
work, and link the resulting change and verification evidence. IDs are stable: keep closed
rows and their decisions so the same idea is not rediscovered as new work.

**Nothing below has been selected for execution by this cleanup.** Items are grouped by
area; their order does not imply priority. A decision/research task is complete when its scope and
outcome are recorded, even when that outcome is to decline implementation. Split accepted
large tasks into linked execution steps under the same ID rather than another competing backlog.

Evidence labels describe what is known, independently of your decision:

- **Gap**: a concrete missing capability is identified in current code or subsystem documentation.
- **Qualification**: implementation exists, but the stated manual, hardware or platform evidence is incomplete.
- **Recheck**: an older request or limitation needs confirmation against the current implementation before coding.
- **Idea**: an optional extension, not a defect or promised feature.
- **Decision**: choose scope or revisit an explicit deferral before implementation.

This is a documentation/code reconciliation, not a fresh full product or hardware audit.
Sources can disagree; later subsystem behavior and execution reports take precedence over
older task instructions. Recheck evidence when starting a task. Existing ADRs and deliberately
unsupported behavior remain in force until explicitly revised.

## Maintaining this list

When work finishes, mark its row with the result and evidence, update the relevant subsystem
guide, and retain the ID. When discovering a new idea, search this list and the source ledger
before adding it. Historical archives preserve their original wording and dates; they are
not instructions to execute obsolete designs. Hardware checks must record the host, firmware,
board and observed outcome, including failures and environmental skips.
